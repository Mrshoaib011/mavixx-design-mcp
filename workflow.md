# Resolved brief and execution

Use the single read-only `templates.sqlite3`. Run the importer only to update the library from a new authorized workbook; ordinary creation must not reimport it. No old template/reference JSONL libraries are included. Every source field is preserved; actual count is 4,057, plus one header in the supplied worksheet.

Read input, apply the automatic 0–10% Intelligence Gate, resolve output/format and actual assets. Retrieve taxonomy once if needed. Automatically set `selection` fields in ordered taxonomy → format → purpose → style → dominant colors → HEX sequence. Query up to three candidates, read the chosen full record, then resolve its analysis/reconstruction/reusable guidance into one current design. The script is an internal plan builder, not an image renderer.

The JSON brief requires `output` (`post`, `story`, `carousel`, `flyer`, `print`, `logo`), `brand`, `subject`, `ratio` for non-logos, `color_roles` (`background`, `content`, `highlight`), and `composition` (`mode`, `subject_placement`, `content_placement`). Provide `selection` with any supported relevant fields: `primary_category`, `primary_subcategory`, `secondary_category`, `secondary_subcategory`, `content_format`, `purpose`, `source_style`, `colors`, `hex_palette`. Secondary classifications can be omitted. Metadata uses known source values and contextual judgment; constraints from the real current brief have higher priority.

After `creative_library.py templates --brief brief.json`, retrieve a full ID and set `template_id` so the adaptation is bound to the record actually read. If omitted, the composer selects the highest-ranked record automatically; still read it and resolve its guidance before generation. `template_adaptation` needs concrete `analysis_transfer`, `reconstruction_transfer`, `reusable_transfer`, and `copy_replacement`. It is a current integrated plan, not raw source excerpts. Put all current actual text in `copy`; nothing from `visible_text` is output copy automatically. Historical facts and [UNREADABLE] are never rendered. Raw source reconstruction can conflict with its metadata or instruct the old ratio; obey the requested output and current resolved adaptation.

Optional `style` applies a named catalog style; otherwise adopt source design language. An external requested style uses `custom_style_rules` with `core`, `typography`, `finish`, `palette`. For requested variations, `variation.master_system` governs campaign identity, independent of the alternate template's cosmetics. Use an exact user instruction in `color_rule_override` only when it genuinely conflicts with the default colors.

After master delivery, retain its `copy`, `composition`, editable headline/supporting-copy keys and fixed CTA/logo/footer anchors in `master_system`. For every variation resolve fresh creative wording, a changed main layout, unchanged fixed anchors and any themed background change before composition. Include `previous_member_copies` for earlier outputs in that batch. An explicit current exact-copy instruction uses the documented override; otherwise no extra copy-permission question is needed. Read references/variation-system.md for the required schema, factual locks and final visual checks.

Each `assets` entry has `role` (`product`, `logo`, `reference`) and an actual `path`. Product `background_removal` is `yes`, `no` or `already_transparent`. Yes needs explicit retained `scope`. Privately prepared cutouts need `cutout_verified: true`; never set it before inspection. If a separate edit would expose an unwanted intermediate, use the inspected original image, explicit scope and `isolation_in_final: true` instead of claiming a verified cutout. No retains the original scene. A supplied logo requires `outer_background_verified: true` after inspection/preparation or `outer_background_in_final: true` for removal within the final render. These flags record distinct completed/planned actions. Inspect the finished isolation and real identity afterward.

Use exact dimensions/ratio and one coherent scene. For carousels record `slide_count` (default five) and resolve actual slide-specific copy before separate generation. Logos use square PNG with true alpha and a dedicated mark/wordmark structure, while borrowing appropriate template typography/brand principles rather than post copy blocks. Available scripts can plan a logo without querying a named style.

Keep every preparation/result-check artifact internal where the host allows; only final graphics and necessary choices reach the normal response. The image-generation host may automatically display tool outputs, so prefer a single final asset render when intermediate hiding is unavailable. Actual image latency and pixel fidelity are host-dependent. Do not claim visual inspection of source previews that are not included.
